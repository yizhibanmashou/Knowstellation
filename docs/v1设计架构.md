### 2.3 dependency JSON 结构

每个章节一个文件，结构如下：

```json
{
  "chapter_id": "chapter10",
  "version": 1,
  "generated_at": "2026-05-15T10:00:00Z",
  "formulas": [
    {
      "id": "formula_10.1a",
      "latex": "\\pi_{i}=4N_{e}\\mu_{i},\\qquad D_{i}=2t\\mu_{i}",
      "label": "Formula 10.1a",
      "section": "10.2",
      "subsection": "10.2.1",
      "position": 3,
      "context_text": "Under the neutral equilibrium model...",
      "symbols_used": ["\\pi_i", "N_e", "\\mu_i", "D_i", "t"],
      "symbols_defined": ["\\pi_i", "D_i"]
    }
  ],
  "dependencies": [
    {
      "dependent_id": "formula_10.1a",
      "prerequisites": [
        {
          "type": "formula",
          "target_id": "formula_3.5",
          "via_symbol": "N_e",
          "relation": "defines_symbol",
          "reason": "N_e defined in Chapter 3, nearest upstream definition",
          "confidence": 0.85,
          "cross_chapter": true
        },
        {
          "type": "variable_definition",
          "symbol": "\\mu_i",
          "definition": "neutral mutation rate at locus i",
          "source": "nearby_text",
          "source_chunk_id": "chapter10_003_block_01",
          "confidence": 0.78
        },
        {
          "type": "variable_definition",
          "symbol": "t",
          "definition": "divergence time between species",
          "source": "nearby_text",
          "source_chunk_id": "chapter10_003_block_01",
          "confidence": 0.82
        }
      ]
    }
  ],
  "symbol_index": {
    "\\pi_i": ["chapter10_pi_i_001"],
    "N_e": ["chapter3_N_e_001"],
    "\\mu_i": ["chapter10_mu_i_001"]
  },
  "ambiguous": []
}
```

**`ambiguous` 字段说明**：当某个公式中的一个符号存在多个候选定义源且系统无法自动判断时（如同一章节内 `α` 既可能是"显著性水平"也可能是"形状参数"），候选列表填入此字段供人工审核。v1 pipeline 不填充此字段（留空数组 `[]`），为 v2 的 Symbol Sense 语义消歧预留接口。

### 2.5 符号抽取规则（Step 2 详细）

**输入**：一条 LaTeX 公式字符串

**抽取策略**：**基于 LaTeX AST 的结构化提取**（不使用纯正则，`pylatexenc` 解析 AST）

**提取步骤**：

**Step 2a — AST 解析与符号提取**：
1. 将 LaTeX 输入 `pylatexenc` 解析为 token 树
2. **预规范化 pass**（在符号提取之前，解决 LaTeX 同义书写问题）：
   - **下标提升**：`\hat{y_i}` → 规范化为 `\hat{y}_i`（将修饰符 group 内的下标提升到外层）
   - **上/下标顺序统一**：`x^{a}_{b}` → `x_{b}^{a}`（先下标后上标，固定顺序）
   - **单字符修饰符包裹**：`\hat y` → `\hat{y}`（确保裸字母被包裹）
   - **嵌套修饰符展平**：`\mathbf{\mathcal{X}}` → 核心 X，记录修饰符集合 {mathbf, mathcal}（顺序无关）
   - 规范化不改变最终 KaTeX 渲染的结果，仅用于符号提取的一致性
3. 遍历规范化后的 AST，区分节点类型：
   - **结构命令**（跳过节点自身，递归处理子节点）：`\frac`, `\sum`, `\int`, `\prod`, `\lim`, `\sqrt`, `\left`, `\right` 等
   - **修饰符命令**（提取被修饰的符号核心）：`\hat`, `\bar`, `\tilde`, `\dot`, `\vec`, `\mathbf`, `\boldsymbol`, `\mathrm`, `\mathcal`, `\mathbb` 等
   - **符号字面量**（直接记录）：希腊字母宏（`\alpha`, `\beta`, `\mu` 等）、单字母变量 `a-zA-Z`
   - **上下标**：附着于父符号，不独立成节点
3. 规范化：读取修饰符链 → 构建完整符号路径（如 `\mathbf{\hat{y}}` → 核心 `y`，保留修饰信息供消歧用）
4. 分类 `symbols_defined`：基于 AST 中等号/赋值号左侧位置启发式判断

**过滤规则**（在 AST 遍历时应用）：
- 跳过结构命令节点自身
- 跳过数字字面量、括号/分隔符、关系/运算符 token
- 求和/积分索引变量（如 `\sum_i` 中的 `i`）暂不处理

**Step 2b — Symbol Sense 家族关系（v1 最简版）**：
从 AST 解析出的每个符号，额外生成一个 **`family_key`**（家族标识）：

```
family_key = strip_modifiers(symbol)
```

剥离规则：
| 原始符号 | family_key | 说明 |
|----------|-----------|------|
| `σ²` (`\sigma^2`) | `σ` | 去掉上标 |
| `ŷ` (`\hat{y}`) | `y` | 去掉修饰符 |
| `\mathbf{\hat{y}}_{ij}` | `y` | 去修饰符 + 去下标 |
| `x_i` | `x` | 去下标 |
| `N_e` | `N` | 去下标 |
| `π` (裸符号) | `π` | 保持原样 |
| `\mathbb{E}` | `E` | 去花体 |
| `\bar{x}^2` | `x` | 去修饰符 + 去上标 |

**用途**：
- 全局符号索引按 `family_key` 组织，而非仅按完整符号
- 匹配优先级：**完整符号精确匹配** > **family_key fallback 匹配**
- family_key 匹配成功的依赖边用较浅的颜色/虚线标注，与精确匹配的实线区分

**为什么用 AST 而非正则**：LaTeX 存在深度嵌套结构（如 `\mathbf{\hat{y}_{ij}}` 或 `x_{i,j}^{a+b}`），纯正则难以正确剥离修饰符链并提取核心符号。`pylatexenc` 将公式解析为 token 树后，修饰符父子关系、上下标附着关系都是结构化的，提取准确率远超正则。

**依赖**：`pylatexenc`（MIT License，`pip install pylatexenc`）

**示例**：

```
输入：\sigma^2 = \frac{1}{n}\sum_{i=1}^{n} (x_i - \mu)^2
AST 提取：
  symbols_defined：[σ²]          family_key：[σ]
  symbols_used：   [n, xᵢ, μ]    family_keys：[n, x, μ]

输入：\mathbf{\hat{y}}_{ij} = a x_{i}^{b}
AST 提取：
  symbols_defined：[ŷ_ij]         family_key：[y]
  symbols_used：   [a, xᵢ, b]    family_keys：[a, x, b]
```

### 2.8 跨章符号依赖（继承信号）匹配策略

**v1 目标**：识别公式中使用了前面章节定义的符号，连接跨章依赖边。

**匹配规则**（结构化信号，不依赖 NLP 语义消歧）：

| 信号 | 规则 | 说明 |
|------|------|------|
| **完整符号精确匹配**（优先） | `\hat{y}` 精确匹配 `\hat{y}`，`π_e` 精确匹配 `π_e` | 修饰符合下标完全一致，高置信度 |
| **family_key fallback 匹配** | `family_key(y)` 匹配 `family_key(ŷ)`、`family_key(σ²)` 匹配 `family_key(σ)` | v1 Symbol Sense 家族关系，识别同一符号家族（标准差 σ²↔σ、估计值 ŷ↔y） |
| **章节 scope 优先级** | 从当前章节向前搜索（Ch N → N-1 → N-2 → …），最近的定义排在前面 | 但**所有匹配到的源都连入图谱**（不止最近一个） |
| **排除局部变量** | 求和索引 `i, j, k`、迭代变量不进入全局索引 | 减少噪音 |

**匹配优先级**：
1. 先去全局索引中做**完整符号精确匹配**（修饰符+下标一致）→ 不受 stoplist 限制，始终生效
2. 精确匹配无结果 → 用 `family_key` 在全局索引中查找家族成员
3. family_key 也无结果 → 标记 `[?]`

**全局 Stoplist**（仅限制跨章 family_key fallback 匹配，精确匹配不受限）：
进化生物学教材中大量单字母变量被反复重载（如 `s` 可能是选择系数/标准差/样本标准差），开启跨章 family_key 匹配会产生大量幽灵依赖边。以下 `family_key` 在跨章场景下**禁用 family_key fallback**：

```
Stoplist: n, N, m, s, t, p, q, r, k, x, y, z, w, u, v, f, g, h
          α, β, γ, δ, ε, λ, μ, τ, ω
          i, j, k, l
```

例如：
- `N_e`（精确匹配 `N_e`，family_key=`N`）→ 跨章精确匹配成功 ✅，不触发 stoplist
- 裸 `N` 的跨章 family_key 匹配 → family_key `N` 在 stoplist 中 → ❌ 不连接
- `N` 在当前章节内有定义 → 章内 family_key 匹配 → ✅ 不受 stoplist 限制（stoplist 仅限跨章）

**边的视觉区分**：
- 精确匹配跨章边：虚线 + `#6366f1`（靛蓝），via 标签标注完整符号名
- family_key 匹配跨章边：虚线 + `#a5b4fc`（浅靛蓝），via 标签标注 `(via family: σ²→σ)`

**处理流程**：
1. 对每个公式，提取 `symbols_used` 中未被章内定义的符号
2. 去全局符号索引中查找（索引按 `family_key` 组织）：
   - **Step A**: 完整符号精确匹配（修饰符+下标一致）
   - **Step B**: 精确匹配无结果 → `family_key` fallback 匹配（去掉修饰符/上下标后匹配家族成员）
   - **Step C**: 仍无结果 → 标记 `[?]`
3. 匹配结果分类：
   - **精确匹配 ≥1 个候选**：全部连入图谱，用虚线 `#6366f1`
   - **family_key 匹配 ≥1 个候选**：全部连入图谱，用虚线 `#a5b4fc`，标签标注 `(via family: σ²→σ)`
   - **0 个候选**：在节点上标灰色小标记 `[?]`
4. hover 任意跨章边时浮出远程公式卡片预览（编号 + LaTeX + context）
5. 输出到 dependency JSON 的 `cross_chapter_edges` 字段

**示例**：
```
Chapter 10, Formula 10.1 使用了 π_n
  → 章内未定义
  → 全局索引搜索 π_n（修饰符一致、下标一致）
  → 匹配到：Ch3 Formula 3.5、Ch8 Formula 8.2
  → 图谱中连两条虚线：3.5 --π_n--> 10.1、8.2 --π_n--> 10.1
  → hover 虚线浮出 3.5 的卡片预览（编号 + LaTeX + "Chapter 3 定义"）
```

**边线渲染**：
- 章内边：实线，`#94a3b8`，1.5px
- 跨章边：**虚线**，`#6366f1`（靛蓝色），2px，via 标签标注符号名

**Edge Flow Animation（Codex Prompt）**：
- 默认状态下边保持静态
- 当用户 Hover 到某条边、或 Hover 到某个前置公式节点时，该路径**必须**触发微弱的流动动画（Marching Ants effect）
  - 实现方式：`stroke-dasharray: 8 4` + `stroke-dashoffset` 动画（CSS `@keyframes` 或 SVG `<animate>`）
  - 方向严格从左向右（从前置公式流向当前公式）
- 跨章依赖（cross_chapter）的虚线，采用不同颜色发光效果（`filter: drop-shadow(0 0 3px #6366f1)`），突出跨越物理章节的知识连接


### 2.6 精选公式选择策略

**目标**：从 2248 条公式中选出 80-120 个放在 3D 星体上

**选择标准**：
1. **每章至少 X 个**：按章节长度比例分配，最短章至少 2 个，最长章不超过 6 个
2. **优先选择有连入边的公式**（被其他公式依赖的核心公式）
3. **优先选择有明确语义标签的公式**（如 "HKA test"、"Hardy-Weinberg equilibrium"）
4. **覆盖章内主要主题**（每个 subsection 至少一个代表）

**产出**：`featured_formulas.json`
```json
{
  "featured": [
    {
      "id": "formula_10.2a",
      "chapter": "10",
      "label": "HKA test statistic",
      "display_name": "HKA Test",
      "importance": 0.92
    }
  ]
}
```

**动态替换**：星体基准集非固定。用户搜索到不在基准集内的公式并点击进入时，该公式被临时插入基准集（替换同章节 `importance` 最低的一个），星体转场将该章节扇形区域刷新。关闭公式卡片后恢复默认精选集。参见 §3.4 动态替换机制。

### 3.2 路由设计
```
/                              → 首页 (3D 星体 + 搜索 + 路线)
/graph/:focusFormulaId         → 图谱展开视图（仅指定焦点公式）
/graph/:focusFormulaId?path=:pathId → 从路线进入，带路线上下文
```

**约束（🚫 禁止将展开节点 ID 批量塞入 URL）：**
- URL 仅用于保存核心上下文，格式限定为 `/graph/:focusFormulaId?path=:pathId`
- ❌ 禁止：`?expanded=id1,id2,...` 参数（URL 长度不可控，且会触发并发加载风暴）
- ✅ 允许：`?path=:pathId` 是**路线 ID** 而非展开节点列表，长度固定
- 画布的局部展开拓扑树（Expanded Tree）保存在内存中（Zustand store：`expandedNodeIds: Set<string>`）
- 当用户刷新页面或通过分享链接进入时，只渲染 focusFormulaId 节点（如果带有 pathId 则一并渲染路线进度条），用户可从该节点重新开始探索
- 这是一种设计取舍：**确定性着陆**优先于**精确回放**

### 3.4 3D 星体详细设计

**实现**：Three.js - `Scene → Camera → SphereGeometry → Point/Mesh`

**球体**：
- **地球色渐变球体**：海洋蓝绿渐变（`#1a5276` → `#2e86c1` → `#27ae60` → `#8B7355`），模拟地球卫星图的色彩印象
- **半透明材质**：`MeshStandardMaterial` with opacity ~0.85，带 Fresnel 边缘发光效果
- 球面散布精选公式节点（小光点/小球体，按章节分色）
- 大小：占据视口中央 ~60% 区域

**背景三层结构**（从后往前）：
1. **第一层 - 宇宙底基**：深色星空背景（`#06060f` → `#0d1117` 渐变），点缀微弱星光粒子
2. **第二层 - 进化生物元素**：低透明度（opacity 0.08-0.15）在背景中融入进化树剪影、DNA 双螺旋线稿、古生物化石轮廓等元素，使用 CSS `background-blend-mode` 或 Three.js texture overlay 与星空层混合
3. **第三层 - 3D 公式星体**：转动的地球色球体 + 公式节点悬浮其上

**进化生物元素细节**：
- 进化树剪影：极细白色线条的分叉树形，不透明度 ~0.1，置于球体后方偏左
- DNA 螺旋：`#1a5276` 色系的半透明双螺旋装饰线，置于背景右上角
- 整体效果：既保持暗色宇宙基调，又暗示"生命演化"主题

**节点**：
- 每个公式节点是一个小圆点/小球体（Three.js `SphereGeometry(0.02, 8, 8)` 或 `Sprite`）
- 颜色：按章节分色（如 Chapter 1-5 蓝色系，Chapter 6-10 绿色系...），形成色带
- 分布算法：Fibonacci sphere（黄金角度螺旋），确保等距均匀分布
- 动画：
  - 整体绕 Y 轴缓慢自转（~0.1 rad/s）
  - 鼠标悬停节点 → 节点脉动放大 + 发光（emissive glow）
  - 鼠标悬停 → 浮出 tooltip（HTML overlay 定位）

**相机**：
- 初始距离：球体占视口 ~60%
- 无用户旋转控制（保持球体神秘感），仅水平悬停时微调
- 平滑的景深效果

**动态替换机制**（搜索驱动的星体节点替换）：
- 基准集：80-120 个每章精选公式（见 §2.6），静态分布在球面上
- 当用户搜索到某个不在基准集中的公式（如 `15.7b`）并点击进入时：
  1. 该公式被**动态插入**到基准集（踢掉同章节基准集中重要性最低的一个，或同章节节点分摊替换）
  2. 球面上该公式所属**章节的整个扇形区域**（按 Fibonacci sphere 上该章节节点的空间邻域）替换为同章节公式（含新插入的公式）
  3. 星体执行一次**转场旋转动画**将目标节点转向用户视野正面
  4. 旋转完成后星体**暂停自转**，目标节点高亮放大 + 公式卡片浮出
  5. 用户关闭卡片 / 点击空白 → 星体恢复自转，节点集合恢复为默认精选集
- 切换过程中其余章节的节点保持不变，仅目标章节区域变化

**旋转转场特效**（不拖沓，0.4-0.8s 完成）：
- 方向：球面上两个弧方向（短弧 / 长弧）各 50% 随机概率选取
- 速度：0.8x-1.5x 随机倍率（同一动画内速度曲线为 ease-in-out）
- 偶尔附加：惯性过冲（overshoot 3-5°，回弹一次）或轻微 Y 轴摆动
- 长弧路径不走直线弧面，可绕经球体背面做一次"环球"路径
- 保证每次特效不重复（记录上次使用的方向/参数，下次排除）

**性能**：
- 使用 `InstancedMesh` 优化 100+ 节点的渲染
- `requestAnimationFrame` 驱动旋转

**🚫 视觉效果修复 — Bloom & DoF（Codex Prompt）**：
- 必须使用 **EffectComposer** 引入后处理管道，消除 Three.js 默认的「塑料感」
- **UnrealBloomPass**：让公式节点发出柔和光晕，而非死板的实心圆点
  - `strength: 0.3`（微光，不过曝）、`radius: 0.5`、`threshold: 0.1`
- **BokehPass / Fog**：制造 3D 纵深感
  - 转到球体背面的节点逐渐融入星空背景（亮度衰减 + 变模糊）
  - 正对屏幕的节点最清晰明亮
- **⚠ 性能约束**：后处理仅在首页激活，图谱视图下 EffectComposer 必须 disposes（节点已休眠时不执行 post-processing pass）
- 参考实现：`import { EffectComposer } from 'three/examples/jsm/postprocessing/EffectComposer'`
- 不可见节点不参与 raycaster 检测
- **🚫 休眠契约**：离开首页时：
  1. `cancelAnimationFrame` 停止自转
  2. 移除全局 `mousemove` 监听器（或通过 ref flag 拦截 `if (isAsleep) return`）
  3. 调用 `renderer.setAnimationLoop(null)` 彻底休眠 Three.js 渲染循环
  4. 返回首页时重新注册监听器 + `requestAnimationFrame(animate)` 恢复
- **🚫 KaTeX 渲染约束（绝对指令）**：
  - **3D 场景**：公式节点只渲染 Three.js 基础几何体（小发光球体），❌ 禁止为所有节点预渲染 HTML/KaTeX
    - 使用 Raycaster 监听 hover 事件，仅在射线击中时挂载**唯一一个** `<Tooltip>` 组件
    - mouseleave 立即卸载 Tooltip 及其内部的 KaTeX 渲染实例
    - **任何时候页面中 KaTeX DOM 实例 ≤ 1 个**（在 3D 场景中）
  - **React Flow 图谱场景**：
    - `FormulaNode` 组件必须用 **`React.memo` + 自定义 compare** 包裹，防止拖拽画布时全量重渲染
    - **`useMemo` + `katex.renderToString`** 缓存 KaTeX HTML，通过 `dangerouslySetInnerHTML` 注入
    - 节点拖拽的视觉反馈仅通过 CSS transform 实现

### 3.5 图谱展开视图详细设计

**配色方案**：
- **画布背景**：浅蓝灰 `#f0f4f8`（冷色调学术背景，降低长时间阅读的视觉疲劳）
- **节点卡片**：白色 `#FFFFFF`，微阴影 `box-shadow: 0 2px 8px rgba(0,0,0,0.08)`，圆角 8px
- **章节标识**：卡片左侧 4px 色条，颜色与首页星体章节色一致（仅作为辅助标识，非主色调）
- **边线**：`#94a3b8`（中度灰蓝），`via` 标签背景半透明蓝灰
- **已选择/聚焦节点**：卡片外发光 `box-shadow: 0 0 0 2px #3b82f6`
- **🚫 视觉闪烁修复（替换旧 fade-out 策略）：**
  - ❌ 废弃「距焦点 > 2 跳则 opacity 降至 0.3」的全局调光（焦点频繁切换导致整屏节点反复亮/暗闪烁）
  - ✅ 改为**高亮溯源路径（Highlight Path）**策略：
    1. 默认所有节点保持 **100% opacity**
    2. 当用户**悬停（hover）**某条边或某个节点时，计算该节点的**完整上游溯源路径**（递归追溯到最远前置）
    3. 上游路径上的节点：保持 100% opacity + 外发光高亮
    4. 不在路径上的节点：opacity 降至 0.25，以弱化而非闪烁的方式降噪
    5. 鼠标离开时：所有节点恢复 100% opacity
  - Variable Definition 节点默认 opacity 0.6（无论是否高亮）

**设计参考**：Notion / Linear / Arc 的信息密度与留白比例，冷灰底 + 白色卡片提供舒适的长时间阅读体验

**工具**：React Flow（推荐，因为节点可以是完整 React 组件 = 轻松嵌入 KaTeX）

**布局算法（🚫 禁止全局 dagre，使用局部相对坐标）：**
- 当前公式作为**焦点节点**（右侧）
- ❌ 废弃全局 dagre 布局算法：每次展开时重新计算所有节点坐标会导致已展开节点「乱飞」
- ✅ 采用**局部相对坐标计算（Local Relative Positioning）**：
  1. 点击公式节点 A 展开前置节点时，获取 A 当前的 (x, y) 坐标
  2. 新拉取的前置节点以 A 为基准，在 A 左侧（x - 300px）按垂直列表均匀排列（y 坐标以 A 为中心上下对称散开）
  3. 已存在于画布上的节点**绝对不允许改变坐标**
  4. 使用 React Flow 的 `addNodes` 和 `addEdges` 增量渲染
  5. 配合 `fitView({ padding: 0.2, duration: 800 })` 将新展开区域平滑居中

  **⚠ 左侧空间挤压 & 碰撞陷阱（深度探索修复）：**
  - 问题：若 B 和 C 都是 A 的前置（x 坐标相同），再分别展开 B→D,E 和 C→F,G，D/E 与 F/G 在 x-600px 处垂直重叠
  - 修复：引入轻量 Y 轴 Slot 占位网格（Slot Grid），在 `useRelativeLayout` 中维护一个 `usedSlots: Map<number, boolean>` 表
    1. 计算新节点的理想 y 坐标 = focusNode.y + index * vGap - offset
    2. 以 y 附近 ±40px 范围查询 usedSlots 是否有冲突
    3. 若冲突则向上/下寻找最近的空闲 Slot（步长 20px，最多 ±200px）
    4. 锁定该 Slot 后写入 usedSlots
    5. 每次展开只在局部范围内运行该碰撞检测，**不扫描全画布**（O(k) k≤新节点数）
  - 简单实现参考（非 d3.forceCollide，避免引入额外依赖）：
    ```typescript
    function findFreeSlot(idealY: number, usedSlots: Set<number>, vGap: number): number {
      for (let offset = 0; offset <= 200; offset += 20) {
        for (const sign of [1, -1]) {
          const candidate = idealY + sign * offset;
          if (!usedSlots.has(Math.round(candidate / 10))) {
            usedSlots.add(Math.round(candidate / 10));
            return candidate;
          }
        }
      }
      return idealY; // 兜底，允许轻微重叠
    }
    ```
- **边路由优化**：对穿层长边和汇聚边使用 `SmoothStepEdge`（贝塞尔曲线拐弯路由），替代直线边减少交叉遮挡；直线边仅用于相邻层之间的简单 1→1 依赖
- **边分层渲染**：via 标签边渲染在 z-index 底层，主线边在高层，避免标签遮挡关键连线
- **🚫 视觉闪烁修复（替换旧 fade-out 策略）：**
  - ❌ 废弃全局跳数调光（焦点切换导致闪烁）；改为**悬停高亮上游溯源路径**（详见配色方案章节）
  - 默认所有节点 100% opacity
  - Hover 节点/边时：上游路径 100% + 外发光，非路径节点 25% opacity
  - 鼠标离开：全部恢复 100%
- 每次展开只计算一跳（新节点追加，已存在节点不移动）
- 多入边时自动处理避免重叠

**⚠ KaTeX 重渲染性能修复（React Flow 高频刷新场景）：**
- 问题：React Flow 在拖拽画布或节点时，高频触发节点组件重渲染。KaTeX 的 LaTeX→HTML 解析在 React 生命周期中相对昂贵，几十个节点同时重渲染会导致平移画布时掉帧
- ✅ 修复：`FormulaNode.tsx` **必须**使用以下优化手段：
  1. **`React.memo`** 包裹整个组件，配合自定义比较函数 `(prev, next) => prev.id === next.id && prev.data.latex === next.data.latex && prev.selected === next.selected`
  2. **`useMemo` + `katex.renderToString`** 缓存 KaTeX HTML：在组件内将 LaTeX 字符串转换为 HTML 字符串并缓存，通过 `dangerouslySetInnerHTML` 注入，避免每次渲染都调用 KaTeX 解析器
  3. 节点拖拽过程中的视觉反馈（阴影、缩放）仅通过 CSS transform 实现，不触发组件重渲染
- **性能边界**：画布平移时无 KaTeX 重解析；节点选中/取消选中时最多触发 1-2 个节点的 KaTeX 重渲染

**⚠ 排版约束（Codex Prompt — 字体与 KaTeX 容器隔离）：**

- KaTeX 数学公式默认使用衬线体（Computer Modern），与 UI 字体形成视觉冲突

### 3.6 搜索功能设计

**前端实现**：全量索引加载 + Fuse.js 模糊匹配（Web Worker）

**⚠ 主线程阻塞风险修复：**
- 问题：formula_search_index.json（含 latex_preview + context + keywords，可能 2-5MB）在实例化 `new Fuse(data, options)` 时，构建内部索引树会占用大量 CPU cycles，直接在组件 mount 时同步执行会导致进入页面掉帧数百毫秒
- ✅ 修复：将 Fuse.js 的初始化和查询逻辑抽离到 **Web Worker** 中
  1. `SearchWorker.ts`：在 worker 内加载 JSON + 实例化 Fuse，监听主线程 `postMessage` 搜索请求
  2. 主线程通过 `worker.postMessage({ query })` 发送搜索词
  3. Worker 返回匹配的 ID 列表（`postMessage({ results })`）
  4. 主线程仅负责展示结果，**3D 星体动画不受任何搜索操作的阻塞**
  5. 返回结果后主线程再根据 ID 查局部缓存获取完整 KaTeX/context（减少 Worker ↔ 主线程的数据传输量）
- **性能边界**：即使搜索词每 100ms 变更一次（快速输入场景），Worker 内部的防抖 + 异步响应也能保证 3D 动画 0 卡顿
- **降级方案**：若浏览器不支持 Worker（极少），回退到主线程同步 Fuse + `requestIdleCallback` 延迟初始化

**索引结构**（`formula_search_index.json`）：
```json
[
  {
    "id": "formula_10.2a",
    "number": "10.2a",
    "chapter": 10,
    "section": "10.2",
    "label": "HKA test statistic",
    "latex_preview": "X^2 = \\sum_i ...",
    "context": "More formally, the HKA test statistic...",
    "keywords": ["HKA", "test", "polymorphism", "divergence", "neutral"]
  }
]
```

**搜索行为**：
- 输入即搜（debounce 200ms）
- 支持：编号精确匹配 + LaTeX 片段 + 关键词 + 章节号
- 结果排序：编号精确匹配 > 标签匹配 > 关键词匹配 > 上下文匹配
- 键盘导航：↑↓ 选择，Enter 确认，Esc 关闭
- 搜索结果随页面切换保留（从首页跳到图谱再回来，搜索结果不丢失）

### 3.7 路线进度条设计

**设计理念**：Apple 风格的非评判式进度指示——不设"已学/未学"标签，不强迫按顺序学习。进度条提供导航，不施加压力。

**位置**：图谱视图底部，固定在视口

**形态**：
```
┌─────────────────────────────────────────────────────────────────┐
│ 📐 群体遗传学基础                                    [折叠 ▲]  │
│                                                                 │
│  ●────●────◉────○────○────○                                    │
│ 1.HWE 2.AF 3.W-F 4.N_e 5.Drift 6.Mut                          │
│                                                                 │
│         ◀ 当前: Wright-Fisher 模型 (3/6) ▶                      │
└─────────────────────────────────────────────────────────────────┘
```

**元素**：
- 路线名称（左侧，可折叠收起进度条 → 图谱获得更多垂直空间）
- 横向节点链：圆点 + 连接线
  - **绿点 `●`**：用户之前浏览过的公式（非"已学"，仅表示"你来过"）
  - **脉冲环 `◉`**：当前正在图谱中展示的公式（蓝/金色脉冲动画，1.5s 周期，呼吸式缩放）
  - **空圈 `○`**：尚未访问的公式（灰色，不暗示需要学，只是"还没到"）
- 圆点下方显示公式简称（如 `1.HWE`、`2.AF`），可点击跳转到该公式的图谱视图
- 底部状态行：当前公式全名 + `(当前位置/路线总长)` + 左右导航箭头

**交互**：
- 点击任意圆点（绿/空/当前均可）→ 自由跳转到该公式，刷新图谱
- 点击 ◀ ▶ 箭头 → 前进/后退一步，沿路线顺序移动
- 底部状态行始终可见，即使在图谱展开多层依赖后也不被遮挡
- 折叠后仅显示路线名称和当前位置小圆点，释放垂直空间
- 进度条高度：折叠态 40px，展开态 110px

### 4.1 首页 → 图谱

```
用户点击星体节点 / 搜索结果 / 路线卡片
  │
  ├─ 星体节点点击：
  │   formulaId → router.push(`/graph/${formulaId}`)
  │
  ├─ 搜索结果点击：
  │   formulaId → router.push(`/graph/${formulaId}`)
  │
  └─ 路线卡片点击：
      pathId → router.push(`/graph/${path.formulas[0].id}?path=${pathId}`)
```

### 4.2 图谱内部展开

```
用户点击 Formula Node
  │
  ├─ 前端检查：该公式的 dependency 是否已加载？
  │   ├─ 是 → 直接渲染新节点 + 边
  │   └─ 否 → fetch(`/data/dependency/chapter${X}_dependencies.json`)
  │           → 缓存到内存 Map<formulaId, deps>
  │           → 渲染新节点 + 边
  │
  └─ React Flow 的 addNodes / addEdges API 追加新元素
      → 局部相对坐标计算新位置（已存在节点坐标绝对不变）
      → 动画过渡
```

### 4.3 数据加载策略

```
应用启动时：
  ├─ 预加载 formula_search_index.json (必需)
  ├─ 预加载 featured_formulas.json (星体数据)
  └─ 预加载 learning_paths.json (路线数据)

图谱视图进入时：
  └─ 按需 (lazy) 加载对应章节的 dependency JSON
     (总共 36 个文件, 每个 ~50-200KB)
```

## 6. 关键设计决策汇总

| 决策 | v1 选择 | 理由 |
|------|---------|------|
| 首页入口 | 3D 星体 + 搜索 + 路线 | 视觉冲击力 + 多种进入方式 |
| 布局方向 | 左→右 | 先修→后修的直觉映射 |
| 展开策略 | 每次一跳 | 避免认知过载 |
| 符号消歧 | 章节 scope + 最近定义 | 简单可靠，歧义标出即可 |
| 前端框架 | React + TypeScript | 生态丰富，React Flow 集成好 |
| 搜索 | 前端 Fuse.js（Web Worker 异步） | 避免主线程阻塞导致 3D 掉帧 |
| 数据加载 | 按需 lazy | 减少初始加载时间 |
| 路线进度条 | 图谱底部固定 | 不干扰图谱交互，始终可见 |
| 跨章符号依赖（继承信号） | ✅ v1 实现 | 全局符号索引匹配 + 严格规则（修饰符一致、下标一致、排除局部变量）；匹配到的全部连入图谱（虚线），未匹配的标 `[?]` |
